Future Vision Document / 将来ビジョン

JANPIAインフラサイトは、
誰のための何になれるか。

申請が難しい、情報が多すぎる、どこから始めればいいかわからない——
現場で積み重なる小さな「壁」を、テクノロジーで取り除く。
このサイトが目指すのは、休眠預金を使って社会を変えたい人たちのインフラになることだ。

Chapter 0

今、ユーザーたちは何につまずいているか

まず出発点を整理する。サイトを使う4つの立場から、現状の「痛み」を見る。

FDO

公募情報・手引きが多すぎて、何から読めばいいかわからない

ADO

自分に関係あるコンテンツがどこにあるか探しにくい

未ログイン一般

制度の全体像がつかみにくく、最初のステップが見えない

JANPIA管理者

コンテンツ更新・ユーザー対応の運用負荷が日々積み重なっている

「AIが人を置き換える」ではなく、
「AIが申請・学習・運営の"壁"を低くする」

JANPIAの利用者は非営利・社会課題領域の団体が中心で、ITリテラシーの差が大きい。
だからこそAIが「専門家に相談できる環境」を民主化するという発想が、このサイトの価値提供として最もフィットする。
機能を増やすためではなく、使う人の時間と自信を守るためにAIを使う。

Chapter 1

短期フェーズ（6〜12ヶ月）

新しい仕組みを作る前に、すでにサイトにある資産をもっとうまく使う。小さく始めて、早く効果を出す。

6〜12ヶ月
今の資産を活かした改善
既存データ・ロジックの組み合わせで、早期に価値を出す
1-1

AI搭載 FAQチャットボット

「休眠預金って何ですか？」「申請の締切はいつですか？」——よくある質問に、24時間いつでも答えてくれるチャット窓口。 すでに蓄積されたFAQデータをそのままAIのナレッジとして活用するため、新たなデータ収集は不要。 よく見られているFAQが自動的に優先学習される循環設計がポイント。

対象未ログイン一般、制度初心者のADO
活用資産FAQデータ、Beacon閲覧ログ
技術方針
Claude API（RAG構成）＋ Beacon APIで収集済みのFAQ閲覧ログを掛け合わせる
★★☆ 難易度：中 既存リソースをそのまま活用できる
1-2

マイページの「次のアクション」提示

ログインしたFDO・ADO担当者に「まだ読んでいない手引きがあります」「申請期限まで2週間です」と自動で教える機能。 現状は自分で探しにいく必要があるが、サイトが先回りして案内する体験に変わる。 AI推論は不要で、既存ロジックの組み合わせで実現できる。

対象FDO・ADO
活用資産ReadModel、公募ステータス判定ロジック
★☆☆ 難易度：低 AIなし、既存ロジックの再構成のみ
1-3

スマート通知（お気に入り × AI要約）

登録カテゴリに新着があったとき、AIが3行で要約して通知する。 「新着5件あります」ではなく、「今月の公募は昨年比で対象地域が拡大しています」という文脈付きの通知に変わる。 情報収集に時間を取れない担当者のための機能。

対象FDO担当者
活用資産既存の通知機能
技術方針
既存のお気に入り通知フローに Claude API の要約呼び出しを組み込む
★☆☆ 難易度：低 Claude APIの呼び出し追加のみ
Chapter 2

中期フェーズ（1〜2年）

このサイトにしかない体験をつくる。「便利なサイト」から「なくてはならないサイト」へ。

1〜2年
新しい体験をつくる
競合サービスにはない、JANPIAインフラサイト固有の価値を構築する
2-1

AI申請書コーチ

最大インパクト

申請書を書く作業は、現状ほぼ完全に「申請者の一人作業」だ。経験がなければ何を書けばいいかわからず、審査側も書き方のばらつきに悩む。 AIが公募の採択基準を読み込み、「この基準に対して、あなたの事業計画のここをもっと具体化しましょう」とリアルタイムでコーチングする。 申請者を鍛えるのではなく、申請のハードルを下げる。

対象申請経験が少ないADO
副次効果JANPIAの審査品質の標準化
活用資産公募ACFフィールド（審査基準・目的）
具体的なUX
「この公募の採択基準はこれです。あなたの事業計画のこの部分を具体化しましょう」「過去の採択事例との類似度はXX点です」
★★★ 難易度：高 公募データとAIコンテキスト設計が鍵
2-2

FDO × ADO マッチングプラットフォーム

「子どもの貧困を解決したいADO」と「教育分野の支援に強いFDO」をつなぐ機能。 現状は公募と応募という一方向の関係だが、テーマや地域で双方向につながれる場に変わる。 AIが活動テーマの類似度を計算し、候補を自動提案する。

対象新規参入のADO、良い団体を探したいFDO
技術方針
団体プロフィール ＋ 埋め込みベクトルによる活動テーマの類似度マッチング
★★★ 難易度：高 新規DB設計・団体プロフィールUIが必要
2-3

社会課題ダッシュボード

「休眠預金はどんな課題を解決してきたのか」を、地図とグラフでインタラクティブに見せる。 採択数・支援額・地域分布を可視化することで、一般市民や政策関係者が制度の価値を実感できる。 透明性が信頼を生む。

対象一般市民、政策関係者
活用資産採択データ、WordPress REST API
★★☆ 難易度：中 D3.js等で可視化、既存データを集計活用
Chapter 3

長期フェーズ（2〜3年）

サイトを超えて、休眠預金エコシステム全体のインフラになる。申請から報告まで、一貫して伴走する。

2〜3年
プラットフォームへの進化
申請の前から採択後まで、ライフサイクル全体を支える
3-1

学習コンテンツのAIパーソナライズ

FDOの担当者は定期的に入れ替わる。新担者が毎回「どこから学べばいい？」と迷う現状を変える。 既読履歴と習熟度スコアを元にAIが最適な学習ルートを提案。 「あなたの段階ならここから始めましょう」と、個人に合わせたロードマップを自動生成する。

対象FDO担当者（特に引き継ぎ直後）
活用資産ReadModel、FdoRoadmap
★★☆ 難易度：中
3-2

事業報告AIアシスト

採択が終わった後の報告書作成も、実は大きな負担だ。 申請時の事業計画データと実績入力を組み合わせて、AIが報告書の下書きを自動生成。 ADOの業務負荷を軽減しながら、JANPIA側も報告品質の標準化が実現する。

対象採択後のADO
副次効果JANPIA審査の効率化
技術方針
申請時の事業計画データ × 実績入力フォーム → Claude APIでドラフト生成
★★★ 難易度：高 報告フォームの新規開発が必要
3-3

対話型制度説明（インタラクティブガイド）

「休眠預金を使いたいが、自分はどのポジションで何をすればいいのかわからない」という初訪問者に向けた機能。 「あなたはどんな課題を解決したいですか？」と問答形式で進むと、自分のポジションと次のステップが自然にわかる。 テキストで説明するのではなく、会話で理解させる。

対象未ログインの制度初心者
★★☆ 難易度：中

Recommended First Step

AI搭載FAQチャットボットを
最初のPoC対象にする

  • 既存FAQデータがそのまま使える。新規データ収集は不要
  • 効果測定が明快。FAQ閲覧数・問い合わせ件数の変化で成否を判断できる
  • JANPIAとして対外的に「AI活用」のメッセージを早期に出せる
  • RAG構成は実績多数。技術的なリスクが低く、失敗コストが小さい
